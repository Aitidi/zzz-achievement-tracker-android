# 筛选分组与城市分类迁移

## 分组（按用户提供的四张图排序）

| 分组 | 子分类 |
| --- | --- |
| 故事 | 法厄同纪事、代理人秘闻、独家视界、代理人信赖、际会之时、绳网热议 |
| 城市 | 绳匠业务、雅努斯区、卫非地、外环地带、索恩区、罗斯凯利法 |
| 战术 | 迷宫诡域、作战技巧、敌对目标、战斗成就、迷失之地、枯萎之都 |
| 探索 | 空洞探索指南、零号密钥、勘域探境 |

筛选面板使用四个分组切换栏。切换分组只切换可见选项，不清除其他组中的已选分类；分组名旁显示该组已选数量。“全部分类”清空所有分类条件，版本条件保持不变。顶部“重置”同时清空版本与分类。

## 合并策略

布亚斯特的 26 条 + 原罗斯凯利法的 5 条 = 31 条罗斯凯利法成就。总数保持 804，分组后的分类总数为 21。

- 原始目录的 ID 和原始分类文本保留在源数据中，以保持历史身份兼容；载入数据时将分类统一为“罗斯凯利法”，并通过现有 Room `syncCatalog` 事务更新本地目录。
- 如果旧目录没有显式 ID，先按原始名称、版本和原始分类计算旧 ID，再转换显示分类；严禁用合并后的分类重新生成旧成就 ID。
- Room 按原 ID 取回完成标记，合并只更新分类，不删除旧条目或创建新 ID。不修改数据库结构，无需破坏性数据库迁移。
- 数据库同步前的 Flow 也会规范化分类，避免启动时短暂出现两种分类。
- 已保存的“布亚斯特”筛选自动转换为“罗斯凯利法”并回写；同时保存了两个名称时自动去重，保留其他已选分类。
- 旧 JSON 备份按原 ID 导入，格式不变；不用重新完成成就，也不用手工改备份。

## 回归覆盖

- 804 条 ID 全量一致、无重复，罗斯凯利法恰好 31 条。
- 无 ID 的旧目录兼容；显式 ID 原样保留。
- 四组覆盖所有现有分类且没有重复，顺序为故事、城市、战术、探索。
- 别名筛选转换、去重、空筛选及重复迁移。
- API 36 模拟器上使用真实 Room 内存数据库：写入旧分类和混合完成状态，连续两次同步目录，逐条比较全部完成标记。
- 在旧数据库状态导出备份，合并后重置再导入，核对应用 804 条且每条完成标记完全恢复。
- 使用独立 SharedPreferences 验证旧筛选偏好转换并回写。

迁移测试使用隔离的内存数据库和测试偏好，不修改用户正式版数据。

验证结果：构建、Lint、6 项单元测试、2 项 API 36 仪器测试全部通过。模拟器界面验证跨组选中“罗斯凯利法 + 作战技巧”显示 87 条，清空后仅选“罗斯凯利法”显示 31 条，探索组显示指定的 3 个子分类。
